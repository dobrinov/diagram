# diagram-review

Colleagues leave comments on diagrams in the editor (press M, then click a node). The comments are stored in the `.diagram` file as `comment` and `reply` lines. This skill closes the loop: comment → prompt → change → resolved.

## Steps

1. List the open threads:
   ```bash
   diagram comments docs/diagrams/checkout.diagram
   ```
2. Get the full task as a prompt. Pick the target that matches the request:
   ```bash
   diagram prompt docs/diagrams/checkout.diagram --target code      # change the codebase
   diagram prompt docs/diagrams/checkout.diagram --target diagram   # change only the diagram
   # big boards: only the commented sections are shown (--context near|section|all to choose)
   diagram prompt docs/diagrams/checkout.diagram --target discuss   # just answer
   ```
   Add `--comment c1,c3` to limit it to some threads. Then follow the prompt.
3. When the design changes, update the diagram with an ops batch. It is applied atomically and `--dry-run` previews it:
   ```bash
   cat > /tmp/ops.json <<'JSON'
   {"ops": [
     {"op": "add_node", "id": "admin", "label": "Admin dashboard", "group": "backend"},
     {"op": "add_edge", "from": "admin", "to": "orders"},
     {"op": "resolve_comment", "id": "c3", "resolution": "Added the admin dashboard"}
   ]}
   JSON
   diagram apply docs/diagrams/checkout.diagram /tmp/ops.json --dry-run
   diagram apply docs/diagrams/checkout.diagram /tmp/ops.json
   ```
   Use `diagram spec` for the full list of ops.
4. Handle every comment you were given:
   - If you addressed it, resolve it: `diagram resolve FILE c1 --note "what you did"`.
   - If it is a question or you disagree, answer it and leave it open: `diagram reply FILE c2 --by agent "…"`.
5. Run `diagram check FILE`, and tell the user what you did for each comment id.

Never delete other people's comments. Resolve them or reply to them instead.
