Map the problem in mindmaps, plan it on kanban and gantt charts, specify it with sequence and ER diagrams — with boards inside boards for the details. Install

Homebrew macOS · Linux

brew install dobrinov/tap/diagram

Later: brew upgrade diagram.

Binaries macOS · Linux · Windows

Grab an archive from the latest release (Apple silicon and Intel, Linux x86_64 and arm64, Windows x86_64), unpack it and put diagram on your PATH.

From source

git clone {{REPO_URL}} diagram && cd diagram
make install

Needs Rust with the wasm32-unknown-unknown target and wasm-pack.

Then run diagram in a repository: it opens the editor in your browser and saves to the file as you work. AI features use the CLI of a subscription you already have (Claude Code, Codex or Gemini CLI) — no API keys.

AI on the subscription you already have

No API keys, no new bill. diagram talks to the CLI you are already signed into — Claude Code, Codex or Gemini — and models read a few lines of outline or ops, never coordinates.

  • Ask AI (⌘K) — say what to change; the answer is tried, retried on errors, and shown as a diff before you keep it
  • Comments → prompts — open review threads become a task for your coding agent
  • Grow a mindmap — ✦ on a topic asks for its next branches
  • Settle a merge — say “their colours, my labels” and the AI picks the sides

Git is the database

A board is one text file. Collaboration is commits and pull requests — and diagram makes them pleasant.

  • Edits rewrite only the lines that changed; your formatting and notes stay
  • --base main draws what a branch changed: green, red, amber
  • diagram merge --install merges boards element by element — most conflicts never happen
  • Real clashes open side by side in the editor; save marks them resolved
  • Links between boards: link: plans/q3.diagram#launch

A small language, made to diff

One statement per line. Write it by hand, draw it in the editor, or let an agent edit it with ops — the file stays as you wrote it, and a pull request shows exactly what changed.

  • Blocks are written as blocks: kanban, gantt, sequence, entity, adr, mindmap…
  • Review threads live in the file: comment on api by ana: …
  • Light and dark themes, presets or your own theme block
# docs/launch.diagram
kanban sprint: Sprint 12 {
  column todo: To do {
    saved: Saved cards [owner: ana]
  }
  column doing: Doing {
    onepage: One-page checkout [blue]
  }
}

gantt launch: Launch plan [start: 2026-10-12] {
  Design [5d, done]
  Build [2w, after: design, done: 40%]
  Launch day [after: build, milestone]
}

entity cards: Saved cards {
  id:          uuid [pk]
  customer_id: uuid [fk: customers, rel: owned by]
}

comment on onepage by mia: Behind a flag?
# in your terminal
$ diagram ask docs/launch.diagram "split Build into API and UI"
# your Claude Code / Codex / Gemini CLI answers with a few ops;
# a reply that does not apply goes back with its error

# comments → a task for your coding agent
$ diagram prompt docs/launch.diagram --target code

# let an agent read a few lines, not the whole board
$ diagram query docs/launch.diagram kind:kanban near:onepage

Made for AI agents

Install the bundled skills and your coding agent knows how to read, draw and grow boards with few tokens: indented outlines for mindmaps, a handful of ops for edits.

diagram skills install          # ./.claude/skills
diagram skills install --global # ~/.claude/skills
  • diagram ask — change a board in words, on your AI subscription
  • diagram prompt — open comments become a task for an agent
  • diagram outline --md — a mindmap as a Markdown prompt
  • diagram brief / query — just the part of a board an agent needs
  • diagram merge — boards merged element by element in git

Embed boards anywhere

One script tag gives any HTML page a board — read-only or the full editor. Everything renders in the browser; nothing is uploaded.

See the example board →

<script src="diagram.embed.js"></script>

<div data-diagram data-mode="view" style="height:420px">
  <script type="text/plain">
    user: Customer [person]
    user -> api: POST /orders
  </script>
</div>

// or from JavaScript
const svg = await Diagram.render(src, { theme: "dark" });
const editor = await Diagram.mount(el, { source: src, mode: "edit" });

// or the npm package (Node and browsers)
import { init, Board } from "diagram";
