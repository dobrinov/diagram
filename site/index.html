A lightweight FigJam for engineers. You can write a diagram in a small, readable language or draw it in the browser. Colleagues comment on boxes and arrows, and one click turns those comments into a prompt your LLM can act on.

Two languages

The DSL is for people: one statement per line, easy to diff in a PR. The JSON model and ops are for programs and LLMs: strict, schema-checked edits that are applied all at once or not at all. Mermaid works in both directions.

A real editor

Double-click to add a box. Drag a dot to connect two boxes, or drop it on empty space to create a new one. You get sticky notes, groups, an inspector, undo, a live code pane, light and dark themes, and pan and zoom.

Comments → prompts

Press M and click anything to start a thread. Prompt turns the open threads into a task for an agent: change the diagram, change the code, or just discuss. Paste the reply back and the changes are applied and the comments resolved.

Export anywhere

Export SVG and PNG, or a single self-contained HTML file. You can also copy Mermaid for GitHub, copy a Markdown brief for LLM context, or share a link that carries the whole diagram in the URL.

Git-aware

diagram svg arch.diagram --base main draws what a branch changed: green for added, red for removed, amber for changed. diagram diff prints the same changes as Markdown.

A library

Use the Rust crate on servers, or one diagram.embed.js file (JS plus WASM) to render diagrams or mount the full editor in your app. It is the same engine everywhere.

The review loop

  1. Draw: diagram docs/checkout.diagram opens the editor and saves to the file as you work.
  2. Review: colleagues comment in the editor, or with diagram comment FILE --on api "…".
  3. Prompt: diagram prompt FILE --target code, or the Prompt button.
  4. Apply: paste the LLM's reply into Apply reply or pipe it to diagram apply FILE. Each comment is resolved with a note on what was done.
